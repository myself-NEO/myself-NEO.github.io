## Problem statement

Design the inventory reservation core for a flash sale: 100 units of a hot product go on sale at midnight, and tens of thousands of buyers click "Buy" in the same second. A click **reserves** a unit for a few minutes while the buyer pays; paying **confirms** it; an unpaid reservation **expires** and the unit goes back on sale. Buyers retry when their network is flaky. The system must never sell more units than exist.

> [!TIP] Try it first
> Write the invariant first: `available + held + sold == total`, always. Then go through each operation (reserve, checkout, cancel, expire) and check that it keeps the invariant even when two of them run at the same moment.

## Clarifying questions

1. Is stock one counter, or individual items (serial numbers)?
2. How long is a reservation held?
3. Limit per buyer?
4. What happens when a buyer retries "reserve" after a timeout?
5. What if payment completes just as the hold expires?
6. Who expires holds — a background job, or lazily?

````reveal title="Answers we'll assume"
- Stock is a **count** of identical units.
- Holds last **5 minutes**.
- **One active reservation per buyer** (a held or bought unit).
- Every reserve request carries an **idempotency key** generated by the client; a retry with the same key returns the same reservation instead of taking another unit.
- Checkout and expiry race on the same reservation: **exactly one wins**. Checkout after expiry fails; a successful checkout can't later expire. Checking out twice is harmless.
- Both: holds are expired **lazily** when touched and by a periodic **sweeper**, so abandoned holds don't sit on stock.
````

## Requirements

**Functional**

1. `reserve(user, qty, key)`: take stock and create a held reservation, or fail (sold out, per-user limit).
2. Retrying `reserve` with the same key returns the original reservation.
3. `checkout(id)`: confirm a held, unexpired reservation; idempotent.
4. `cancel(id)`: release a held reservation.
5. Expired holds return their stock (lazily and via `sweepExpired()`).

**Non-functional**

6. **Never oversell**, under any interleaving.
7. No global lock on the hot path; thousands of concurrent reserves.
8. No leaked stock: every hold ends as sold, released or expired.

## Step 1 — Reservation lifecycle

```states title="Reservation"
[*] --> HELD : reserve [stock available, user has no active reservation]
HELD --> SOLD : checkout [now < expiresAt]
HELD --> RELEASED : cancel / stock += qty
HELD --> EXPIRED : sweep or lazy check [now >= expiresAt] / stock += qty
SOLD --> [*]
RELEASED --> [*]
EXPIRED --> [*]
```

````reveal title="Why compare-and-set on the state?"
Every transition leaves `HELD`, and every one of them has a side effect (stock comes back, or the sale is final). If checkout and the sweeper both read `HELD` and both act, the unit is sold **and** returned to stock — an oversell.

Storing the state in an `AtomicReference` and moving it with `compareAndSet(HELD, X)` makes the transition the decision point: exactly one caller's CAS succeeds, and only that caller performs the side effect. No lock is needed, because the state is a single variable.
````

## Step 3 — Implementation

````hint title="Hint — three atomic steps in reserve"
1. `byKey.computeIfAbsent(key, ...)` — one reservation per idempotency key, even for simultaneous retries. If creation throws, nothing is stored, so the key can be retried later.
2. `activeByUser.putIfAbsent(user, key)` — the per-user limit, claimed atomically.
3. A CAS loop on `available` — take stock only if enough remains.

If step 3 fails, undo step 2. Each step is atomic on its own; the undo keeps them consistent together.
````

````solution title="Complete Java solution"
import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.time.ZoneId;
import java.time.ZoneOffset;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.AtomicLong;
import java.util.concurrent.atomic.AtomicReference;

public class FlashSaleDemo {
    public static void main(String[] args) throws InterruptedException {
        MutableClock clock = new MutableClock(Instant.parse("2026-11-11T00:00:00Z"));
        FlashSale sale = new FlashSale(3, Duration.ofMinutes(5), clock);

        Reservation asha = sale.reserve("asha", 1, "asha-k1");
        System.out.println("asha -> " + asha + "; " + sale.stats());
        System.out.println("asha retries with the same key -> " + sale.reserve("asha", 1, "asha-k1").id() + "; " + sale.stats());
        attempt(() -> sale.reserve("asha", 1, "asha-k2"));
        Reservation ravi = sale.reserve("ravi", 1, "ravi-k1");
        Reservation meera = sale.reserve("meera", 1, "meera-k1");
        attempt(() -> sale.reserve("kabir", 1, "kabir-k1"));
        System.out.println("checkout " + sale.checkout(asha.id()) + ", again -> " + sale.checkout(asha.id()).state());
        sale.cancel(ravi.id());
        System.out.println("ravi cancels; kabir retries his key -> " + sale.reserve("kabir", 1, "kabir-k1"));
        clock.advance(Duration.ofMinutes(6));
        attempt(() -> sale.checkout(meera.id()));
        System.out.println("sweeper expired " + sale.sweepExpired() + " hold(s); " + sale.stats());

        FlashSale doorbuster = new FlashSale(100, Duration.ofMinutes(5), clock);
        List<Reservation> holds = Collections.synchronizedList(new ArrayList<>());
        AtomicInteger soldOut = new AtomicInteger();
        race(16, t -> {
            for (int i = 0; i < 125; i++) {
                String buyer = "buyer-" + t + "-" + i;
                try { holds.add(doorbuster.reserve(buyer, 1, buyer + "-key")); } catch (SaleException e) { soldOut.incrementAndGet(); }
            }
        });
        System.out.println("doorbuster: " + holds.size() + " holds, " + soldOut + " turned away; " + doorbuster.stats());
        race(8, t -> holds.forEach(r -> doorbuster.checkout(r.id())));   // every hold checked out 8 times at once
        System.out.println("after concurrent checkouts: " + doorbuster.stats());
    }

    interface Job { void run(int thread); }

    static void race(int threads, Job job) throws InterruptedException {
        ExecutorService pool = Executors.newFixedThreadPool(threads);
        CountDownLatch go = new CountDownLatch(1);
        for (int t = 0; t < threads; t++) {
            int id = t;
            pool.submit(() -> { go.await(); job.run(id); return null; });
        }
        go.countDown();
        pool.shutdown();
        pool.awaitTermination(30, TimeUnit.SECONDS);
    }

    static void attempt(Runnable action) {
        try {
            action.run();
        } catch (SaleException e) {
            System.out.println("Rejected: " + e.getMessage());
        }
    }
}

class SaleException extends RuntimeException {
    SaleException(String message) { super(message); }
}

enum HoldState { HELD, SOLD, EXPIRED, RELEASED }

final class Reservation {
    private final String id;
    private final String user;
    private final String key;
    private final int quantity;
    private final Instant expiresAt;
    private final AtomicReference<HoldState> state = new AtomicReference<>(HoldState.HELD);

    Reservation(String id, String user, String key, int quantity, Instant expiresAt) {
        this.id = id; this.user = user; this.key = key; this.quantity = quantity; this.expiresAt = expiresAt;
    }

    String id() { return id; }
    String user() { return user; }
    String key() { return key; }
    int quantity() { return quantity; }
    Instant expiresAt() { return expiresAt; }
    HoldState state() { return state.get(); }

    /** The single decision point: exactly one caller can move a reservation out of a given state. */
    boolean transition(HoldState from, HoldState to) { return state.compareAndSet(from, to); }

    @Override public String toString() { return id + " (" + user + " x" + quantity + ", " + state.get() + ")"; }
}

final class FlashSale {
    static final int MAX_PER_ORDER = 2;

    private final int total;
    private final Duration holdFor;
    private final Clock clock;
    private final AtomicInteger available;
    private final Map<String, Reservation> byKey = new ConcurrentHashMap<>();
    private final Map<String, Reservation> byId = new ConcurrentHashMap<>();
    private final Map<String, String> activeByUser = new ConcurrentHashMap<>();   // user -> key of their HELD or SOLD reservation
    private final AtomicLong ids = new AtomicLong();

    FlashSale(int total, Duration holdFor, Clock clock) {
        this.total = total;
        this.holdFor = holdFor;
        this.clock = clock;
        this.available = new AtomicInteger(total);
    }

    Reservation reserve(String user, int qty, String idempotencyKey) {
        if (qty <= 0 || qty > MAX_PER_ORDER) throw new SaleException("quantity must be 1.." + MAX_PER_ORDER);
        // One reservation per key, even for simultaneous retries; a failed attempt stores nothing.
        Reservation r = byKey.computeIfAbsent(idempotencyKey, k -> createHold(user, qty, k));
        if (!r.user().equals(user)) throw new SaleException("key " + idempotencyKey + " belongs to another request");
        return r;
    }

    private Reservation createHold(String user, int qty, String key) {
        if (activeByUser.putIfAbsent(user, key) != null) throw new SaleException(user + " already has a reservation (limit 1 per buyer)");
        if (!takeStock(qty)) {
            activeByUser.remove(user, key);                            // undo the claim
            throw new SaleException("sold out");
        }
        Reservation r = new Reservation("R" + ids.incrementAndGet(), user, key, qty, clock.instant().plus(holdFor));
        byId.put(r.id(), r);
        return r;
    }

    /** CAS loop: never lets the counter go below zero. */
    private boolean takeStock(int qty) {
        while (true) {
            int a = available.get();
            if (a < qty) return false;
            if (available.compareAndSet(a, a - qty)) return true;
        }
    }

    /** Idempotent: checking out a SOLD reservation again just returns it. */
    Reservation checkout(String id) {
        Reservation r = find(id);
        if (!clock.instant().isBefore(r.expiresAt())) end(r, HoldState.EXPIRED);   // lazy expiry, same CAS as the sweeper
        if (r.transition(HoldState.HELD, HoldState.SOLD) || r.state() == HoldState.SOLD) return r;
        throw new SaleException(id + " is " + r.state());
    }

    void cancel(String id) {
        Reservation r = find(id);
        if (!end(r, HoldState.RELEASED) && r.state() != HoldState.RELEASED) throw new SaleException(id + " is " + r.state());
    }

    /** Run every few seconds by a scheduler. */
    int sweepExpired() {
        Instant now = clock.instant();
        int expired = 0;
        for (Reservation r : byId.values()) {
            if (r.state() == HoldState.HELD && !now.isBefore(r.expiresAt()) && end(r, HoldState.EXPIRED)) expired++;
        }
        return expired;
    }

    /** HELD -> RELEASED or EXPIRED. Only the caller whose CAS wins returns the stock. */
    private boolean end(Reservation r, HoldState to) {
        if (!r.transition(HoldState.HELD, to)) return false;
        available.addAndGet(r.quantity());
        activeByUser.remove(r.user(), r.key());
        return true;
    }

    String stats() {
        int held = 0;
        int sold = 0;
        for (Reservation r : byId.values()) {
            if (r.state() == HoldState.HELD) held += r.quantity();
            if (r.state() == HoldState.SOLD) sold += r.quantity();
        }
        return "available " + available.get() + ", held " + held + ", sold " + sold + " (total " + total + ")";
    }

    private Reservation find(String id) {
        Reservation r = byId.get(id);
        if (r == null) throw new SaleException("no reservation " + id);
        return r;
    }
}

final class MutableClock extends Clock {
    private volatile Instant now;
    MutableClock(Instant start) { now = start; }
    void advance(Duration d) { now = now.plus(d); }
    @Override public Instant instant() { return now; }
    @Override public ZoneId getZone() { return ZoneOffset.UTC; }
    @Override public Clock withZone(ZoneId zone) { return this; }
}
```
````

## Design decisions

- **Stock is one `AtomicInteger` with a CAS loop.** "Read, check ≥ qty, write" happens atomically without a lock, so thousands of buyers can reserve in parallel and the counter can never go negative (see [Locks and atomics](lesson:locks-and-atomics)).
- **Reservation state is an `AtomicReference`.** Every transition out of `HELD` is a CAS; the winner performs the side effect. That's how checkout, cancel, the sweeper and lazy expiry can all run at once without double-returning stock (see [Race conditions](lesson:concurrent-state-transitions)).
- **Idempotency key per request.** `computeIfAbsent` creates at most one reservation per key; a retry gets the original back. A failed attempt (sold out) stores nothing, so the same key can be tried again later (see [Idempotency](lesson:idempotency)).
- **Checkout is idempotent too.** A buyer's double-click or a payment webhook delivered twice confirms once and succeeds both times.
- **Expiry is guaranteed, not best-effort.** Lazy expiry handles the reservations people touch; the sweeper handles the abandoned ones. Without it, stock leaks until someone happens to look (see [Resource lifecycle](lesson:resource-lifecycle)).

## Patterns and principles

[State machine](lesson:state-machines) with CAS transitions, [idempotency keys](lesson:idempotency), [Scarcity](lesson:scarcity) (a fixed pool under heavy contention), [Resource lifecycle](lesson:resource-lifecycle) (every hold ends), and lock-free [atomics](lesson:locks-and-atomics).

## Example execution flow

```text
stock 3, hold 5 min
reserve(asha, k1)     key new -> asha claims her slot -> CAS 3->2 -> R1 HELD
reserve(asha, k1)     key exists -> same R1, stock untouched
reserve(asha, k2)     asha already active -> rejected
ravi -> R2, meera -> R3 (stock 0); kabir -> CAS sees 0 -> sold out, key k1 not stored
checkout(R1) x2       CAS HELD->SOLD, then "already SOLD" -> success both times
cancel(R2)            CAS HELD->RELEASED -> stock 1; kabir retries k1 -> R4 HELD
+6 min checkout(R3)   expired -> CAS HELD->EXPIRED (stock back) -> HELD->SOLD fails -> rejected
sweepExpired()        R4 HELD and past expiry -> EXPIRED -> stock back
2000 buyers, 100 units, 16 threads -> exactly 100 holds; 8 threads check out every hold -> 100 sold
```

```text title="Program output"
asha -> R1 (asha x1, HELD); available 2, held 1, sold 0 (total 3)
asha retries with the same key -> R1; available 2, held 1, sold 0 (total 3)
Rejected: asha already has a reservation (limit 1 per buyer)
Rejected: sold out
checkout R1 (asha x1, SOLD), again -> SOLD
ravi cancels; kabir retries his key -> R4 (kabir x1, HELD)
Rejected: R3 is EXPIRED
sweeper expired 1 hold(s); available 2, held 0, sold 1 (total 3)
doorbuster: 100 holds, 1900 turned away; available 0, held 100, sold 0 (total 100)
after concurrent checkouts: available 0, held 0, sold 100 (total 100)
```

## Edge cases

- **Retry with the same key** → the original reservation, whatever its state now (an expired hold stays expired; the buyer needs a new key to try again).
- **Same key from another user** → rejected.
- **Checkout exactly at `expiresAt`** → expired (`now >= expiresAt`).
- **Checkout, cancel and sweeper at the same time** → one CAS wins; stock is returned at most once.
- **Cancelling a sold reservation** → rejected; cancelling twice → harmless.
- **Quantity 0, negative, or above the per-order cap** → rejected.

```java title="FlashSaleTest.java" file="FlashSaleTest.java" test="FlashSaleDemo.java"
import java.util.Collections;

import java.util.concurrent.CountDownLatch;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

class FlashSaleTest {
    private MutableClock clock;

    @BeforeEach
    void setUp() { clock = new MutableClock(Instant.parse("2026-11-11T00:00:00Z")); }

    private static void race(int threads, Runnable body) throws InterruptedException {
        ExecutorService pool = Executors.newFixedThreadPool(threads);
        CountDownLatch go = new CountDownLatch(1);
        for (int i = 0; i < threads; i++) pool.submit(() -> { go.await(); body.run(); return null; });
        go.countDown();
        pool.shutdown();
        pool.awaitTermination(30, TimeUnit.SECONDS);
    }

    @Test
    void sameKeyReturnsTheSameReservation() {
        FlashSale sale = new FlashSale(5, Duration.ofMinutes(5), clock);
        assertSame(sale.reserve("a", 1, "k"), sale.reserve("a", 1, "k"));
        assertEquals("available 4, held 1, sold 0 (total 5)", sale.stats());
        assertThrows(SaleException.class, () -> sale.reserve("b", 1, "k"));
    }

    @Test
    void neverOversellsUnderContention() throws InterruptedException {
        FlashSale sale = new FlashSale(50, Duration.ofMinutes(5), clock);
        List<Reservation> holds = Collections.synchronizedList(new ArrayList<>());
        AtomicInteger n = new AtomicInteger();
        race(32, () -> {
            for (int i = 0; i < 100; i++) {
                int id = n.incrementAndGet();
                try { holds.add(sale.reserve("u" + id, 1 + id % 2, "k" + id)); } catch (SaleException ignored) { }
            }
        });
        int held = holds.stream().mapToInt(Reservation::quantity).sum();
        assertEquals(50, held);
        assertEquals("available 0, held 50, sold 0 (total 50)", sale.stats());
    }

    @Test
    void checkoutAndExpiryRaceHasOneWinnerPerReservation() throws InterruptedException {
        FlashSale sale = new FlashSale(200, Duration.ofMinutes(5), clock);
        List<Reservation> holds = new ArrayList<>();
        for (int i = 0; i < 200; i++) holds.add(sale.reserve("u" + i, 1, "k" + i));
        clock.advance(Duration.ofMinutes(5));                           // exactly at expiry
        race(8, () -> {
            sale.sweepExpired();
            for (Reservation r : holds) {
                try { sale.checkout(r.id()); } catch (SaleException ignored) { }
                try { sale.cancel(r.id()); } catch (SaleException ignored) { }
            }
        });
        assertEquals("available 200, held 0, sold 0 (total 200)", sale.stats());
    }

    @Test
    void cancelAndCheckoutRaceKeepsTheInvariant() throws InterruptedException {
        FlashSale sale = new FlashSale(300, Duration.ofMinutes(5), clock);
        List<Reservation> holds = new ArrayList<>();
        for (int i = 0; i < 300; i++) holds.add(sale.reserve("u" + i, 1, "k" + i));
        AtomicInteger roles = new AtomicInteger();
        race(2, () -> {
            boolean buyer = roles.getAndIncrement() == 0;                // one thread checks out, the other cancels
            for (Reservation r : holds) {
                try { if (buyer) sale.checkout(r.id()); else sale.cancel(r.id()); } catch (SaleException ignored) { }
            }
        });
        long sold = holds.stream().filter(r -> r.state() == HoldState.SOLD).count();
        long released = holds.stream().filter(r -> r.state() == HoldState.RELEASED).count();
        assertEquals(300, sold + released);
        assertEquals("available " + released + ", held 0, sold " + sold + " (total 300)", sale.stats());
    }

    @Test
    void perBuyerLimitIsFreedWhenAHoldEnds() {
        FlashSale sale = new FlashSale(5, Duration.ofMinutes(5), clock);
        Reservation r = sale.reserve("a", 1, "k1");
        assertThrows(SaleException.class, () -> sale.reserve("a", 1, "k2"));
        sale.cancel(r.id());
        sale.reserve("a", 1, "k2");
    }
}
```

## Concurrency

- **The hot path takes no locks:** `computeIfAbsent` (per-key bin lock), `putIfAbsent`, and two CAS loops. Thousands of buyers spread across the map's bins; only the stock counter is shared, and a CAS on one integer is very fast.
- **Heavy contention on one counter:** if CAS retries become a bottleneck, split stock into **buckets** (say 16 counters of 6–7 units) and pick one by hashing the user; when a bucket is empty, try the others. That's [lock striping](problem:concurrent-parking-lot) applied to a counter.
- **Why lazy expiry plus a sweeper?** Lazy expiry keeps checkout correct even if the sweeper is late; the sweeper keeps abandoned stock from staying locked up.
- **In a database:** `UPDATE stock SET available = available - ? WHERE sku = ? AND available >= ?` — the row count tells you whether you got it. Reservation transitions become `UPDATE reservation SET state = 'SOLD' WHERE id = ? AND state = 'HELD' AND expires_at > now()`, the SQL form of CAS.

## Common mistakes and alternatives

- **`if (available.get() > 0) available.decrementAndGet()`** — two threads pass the check with 1 unit left: oversold.
- **Expiry and checkout both reading `HELD` and acting** — sold *and* restocked.
- **No idempotency** — a retried click holds two units for one buyer.
- **Expiry only in a background job** — a checkout one second after expiry still succeeds if the job hasn't run.
- **A global lock** — correct, but every buyer in the world waits in one line at midnight.
- **Alternative:** a queue in front of a single-threaded allocator. Strictly fair (first come, first served) and simple to reason about; throughput limited to one thread, which is often enough for a few hundred units.

## Follow-up questions

````reveal title="Payment in the middle"
Checkout becomes: charge with the reservation ID as the payment idempotency key → CAS `HELD → SOLD`. If the CAS fails (the hold expired while paying), **refund** — the same compensation as in [Movie Ticket Booking](problem:movie-ticket-booking). Alternatively add a `PAYING` state (CAS `HELD → PAYING` before charging) that the sweeper doesn't expire, with a longer timeout of its own.
````

````reveal title="Fairness and bots"
A virtual waiting room in front of the sale admits users in batches with signed tokens; `reserve` requires a valid token. That flattens the spike and lets you rate-limit per account and per device (see [Rate Limiter](problem:rate-limiter)).
````

````reveal title="Many servers"
The counter moves to one place that supports atomic conditional updates: a database row, or Redis (`DECRBY` guarded by a Lua script that checks for negatives). Reservation state lives in the same store so the CAS transitions stay atomic.
````

## Complexity

- `reserve`, `checkout`, `cancel`: O(1) expected (map operations and a CAS loop).
- `sweepExpired`: O(R) for R reservations; index by expiry time (a `DelayQueue` or a time-bucketed map) to make it O(expired).
